# Research Workflow

## 目标

把“我想学习一个新东西”转成一份真正落盘的深度调研报告，而不是停留在聊天回复。

## 执行顺序

1. 读取 `concept-deep-dive-prompt-v5.md`，把它视为默认结构模板。
2. 从用户请求中提取：
   - `concept`
   - `domain`（可空）
   - `target_repo` 或本地代码路径（可空）
3. 读取 `rules/report-style.md`，把 ASCII 表达和篇幅/深度要求视为硬约束。
4. 用 `scripts/prepare_concept_report.py` 生成报告路径。
5. 按 prompt 的 0-8 层执行研究与写作。
6. 把结果保存到磁盘后，再向用户汇报。

## 研究要求

- 第 0-6 层先建立概念的定义、起源、机制、生态位和实践方式。
- 第 7 层必须做“分析型调研”，不是堆链接。
- 第 8 层必须基于真实仓库内容；没有目标仓库时保留本层并明确说明无法完成仓库分析。
- 允许扩展第 7 层的数量，但不要削弱分析深度。
- 只要资料足够，完整报告默认目标不低于 10000 字。
- 论文部分必须明显比其他部分更细，不能用一句贡献概括整篇论文。

## 变量处理

- 用户只给概念名时，`domain` 保持为空，不要强行猜领域。
- 用户没有给仓库时，不要把当前学习仓库硬套成第 8 层分析对象，除非它显然就是被分析的目标项目。
- 用户提供了新 prompt 时，以用户 prompt 为准，但仍遵守本仓库的归档规则。

## 输出要求

- 全程中文。
- 保留 prompt 的编号结构。
- 凡是流程、逻辑、知识地图、因果链、输入输出结构，使用 ASCII 表达，如 `A -> B -> C`。
- 对缺失信息直接说明，不编造。
- 对基于来源推断出来的判断，显式标注“推测”或“基于现有资料判断”。
