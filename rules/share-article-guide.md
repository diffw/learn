# Share Article Guide — Learn in Public 分享文章规范

## 定位

基于概念调研报告，生成可分享到 X.com / LinkedIn 的文章。理念是 Learn in Public：记录学习过程，不是展示专业。

## 输出文件

每个概念生成两篇分享文章，存放在概念目录下：

```text
concepts/<concept-slug>/
  reports/YYYY-MM-DD-deep-dive.md     # 调研报告（已有）
  share-zh.md                          # 中文分享文章
  share-en.md                          # 英文分享文章
```

## 中文文章规范

### 篇幅

- 目标：1,500-3,000 字（阅读 3-6 分钟）
- 硬下限：1,500 字
- 硬上限：5,000 字

### 结构模板

```text
1. 钩子（前 2-3 行）
   一个具体的个人经历或困惑，让读者想读下去

2. 背景 / 动机
   为什么我（一个 UX 设计师）要学这个概念
   我了解这个概念的原因

3. 概念的历史来源
   这个概念从哪来的、谁提出的、关键演进节点
   精简客观，不加个人解读
   让读者感受到概念的分量和时间跨度

4. 概念的核心流程 / 核心定义
   标准的、客观的概念介绍
   可以用 ASCII 流程图表达核心流程
   列出 2-3 个关键子概念，每个一句话
   这一块是全文最「硬」的部分，与前后的个人叙事形成对比

5. 我的理解
   用日常类比解释核心概念
   带上自己的理解和感悟
   承认可能理解不完整

6. 在我的项目中怎么用
   结合真实项目（如 Vibe Capture）做分析
   具体到文件、配置、流程
   产品名称自然出现，不是硬广

7. 几条可以带走的（Takeaways）—— 让人愿意收藏 / 转发的「钩子段」
   见下方「Takeaways 章节规范」详细要求
   章节标题中文用「几条可以带走的（Takeaways）」
   英文用「Takeaways worth saving」

8. 收尾
   简洁，一句话点题或开放性问题
   可自然联结更大的人生叙事
   最后一句必须是「开放性问题 / 邀请共创」，让 thread 有理由延续
```

### 风格

严格遵守 `rules/writing-style.md` 中定义的所有规则。

### Takeaways 章节规范（章节 7 详细要求）

**为什么需要这一章节**

读者从一篇 1,500-3,000 字的文章里能记住的内容有限。Takeaways 是一篇文章被收藏 / 转发的根本理由——读者哪怕只看这一段、甚至只截图这一段，也应该能拿走文章的核心价值。

没有这一段，文章就只是「写完即过期」的内容；有了这一段，文章变成读者愿意 bookmark 的资产。

**定位**

- 全文最后一个有结构的章节，紧贴收尾之前
- 哪怕跳过前面所有章节，只读这一段也能拿走全文核心
- 是文章可被 screenshot / 收藏 / 引用 / 转发的根本原因

**结构**

- 5-7 条编号列表（少于 5 条信息密度不够，多于 7 条记不住）
- 每条结构：**粗体 one-liner** + 1-3 行说明
- One-liner 是反直觉、可记忆、可独立成立的判断
- 说明部分给「具体可执行的下一步 / 论据 / 数字 / 工具名」

**钩子设计原则**

- 不用「学到了 X」「了解到 Y」，用「以后我会 Z」「下次记得 W」「你应该 V」
- 避免抽象空话（「保持学习」「拥抱变化」「赋能」「方法论」「干货」）
- 每一条独立成立——能单独被截图 tweet 出去（每条 ≤ 200 字）
- 至少 1 条带具体数字 / 工具名 / 文件路径 / 命令
- 至少 1 条是「反直觉的提醒」（不是常识，不是「显而易见的事」）
- One-liner 之间互补不重复

**入场句**

Takeaways 章节开头用一句话告诉读者「为什么应该读这段」，例如：

- 「写完这篇我自己留了一份清单。如果你只看这一段，至少把这 N 条带走：」
- 「A checklist I'm keeping for myself. If you only read this section, take these N:」

**收尾段（章节 8）的最后一句**

Takeaways 之后的收尾段，**最后一句必须是开放问题或邀请**：

- 邀请读者分享他们的经验（「也想听听：你的 X 工作流是怎么管的？」）
- 提出值得讨论的开放问题
- 让 thread 有理由延续，让收藏的人有理由回来再读 / 回复

**英文版同样规则**

- 章节标题用「Takeaways worth saving」
- 入场句用「A checklist I'm keeping for myself.」之类的口语化表达
- 不要直译中文 Takeaways——按英文读者节奏重写
- 每条 one-liner 在英文里要更直接、更短

**Takeaways 失败信号**

如果出现以下任何一项，回头重写：

- 任一条只是「常识 / 显而易见」（读者已经知道）
- 任一条是抽象口号没有可执行内容
- 缺少具体工具 / 路径 / 命令 / 数字
- 全部是「正面建议」没有「反直觉提醒」
- 任一条超过 200 字（拆分或压缩）
- 全部 takeaway 都能被一句话「拥抱 AI」概括（说明没有真正不同的判断）

## 英文文章规范

### 篇幅

- 目标：800-1,500 words（阅读 3-6 分钟）
- 硬下限：800 words
- 硬上限：3,000 words

### 语言要求

- 必须符合英语母语用户的语言习惯
- 语气：conversational，非正式但专业
- 避免 press-release 式的官方口吻
- Show, don't tell：用具体例子和数字说话
- 开头即给价值承诺：「Here's what I learned...」
- 每句话推动读者往下读

### 注意事项

- 英文版不是中文版的直译，而是基于同一素材的重新写作
- 保留作者的个人视角（UX designer learning engineering concepts）
- 产品名、项目名保持英文原形
- 适当加入 cultural context（如 design background, indie dev journey）

## X.com 发布策略

### 文章发布

- 使用 X Articles / 长推文功能发布完整文章
- 阅读停留 > 2 分钟可获 20 倍 like 权重（算法友好）
- 2026 年算法不再打压外链，文章类内容被主动推荐

### 配套 Thread（可选）

如果需要同时生成 Thread 版本：
- 5-8 条为最佳
- 每条是完整的思想单元
- 第一条是强钩子，能独立传播
- 最后一条做总结 + 提问

### 发布后

- 发布后 1 小时内积极回复每一条评论（算法权重 150 倍 like）
- 书签收藏权重 20 倍 like
